# Azure CycleCloud version 8.11.0 

This release contains many security-related fixes. It also introduces several new features and resolves existing issues.

## New features 

- The Azure CycleCloud installation wizard UI has been replaced by a new `cycle_server setup` CLI command to make initial installation more secure and easier to script. 
- Azure CycleCloud now supports mounting [NFS-Over-Blob Storage](/azure/storage/blobs/network-file-system-protocol-support-how-to) using the standard `cyclecloud.mounts` configuration syntax in the cluster template (set `address = <storage-account-name>.blob.core.windows.net` and `export_path = /<storage-account-name>/<container-name>`). 
- Azure CycleCloud supports configuring nodes to install the Azure Monitoring Agent Extension upon the VM startup (set `AzureMonitoringAgent.Enabled = true` and `AzureMonitoringAgent.IdentityId = "/subscriptions/<subscriptionID>/resourceGroups/<RG>/providers/Microsoft.ManagedIdentity/userAssignedIdentities/<MI>"`). 
- The Azure CycleCloud **Event Log** UI now offers easy-to-use filter dropdowns for the events table. 

## Resolved problems 
- CycleCloud cluster access APIs allowed unexpected tampering with cluster privileges. 
- The **Back to cluster** button on the **Event Log** page unexpectedly expanded to fill the full horizontal space. 
- CycleCloud allowed clusters to set `Username` and `Password` for the initial Linux node administrator user and ReturnProxy tunnels in the plain-text cluster template. 
- CycleCloud allowed ReturnProxy clusters to be created using `Username` and `Password`, potentially exposing the password. 
- The **Global Node User** and **Global Node Admin** roles incorrectly granted CycleCloud UI access as well as Linux user access on the clusters. 
- CycleCloud did not properly hide node password data provided via cluster templates when copied to certain internal records, potentially leaking the password data. 
- CycleCloud gridengine autoscaler used the autoscaler service account as a command line parameter, potentially exposing the password via `/proc`.  
- CycleCloud Slurm installation did not enforce certificate validation when querying cluster status. 
- The HealthAgent state storage file had permissions that were too loose. 
- When ReturnProxy was enabled, CycleCloud started a tunnel for AMQP connections even though AMQP is no longer supported. 
- The CycleCloud UI read the node hostname from the “installation complete” message rather than the authoritative `NodeProperties` record for the node. 
- Some HPC images caused nodes to fail to converge due to corrupted aznfs package installations. 
- The `cyclecloud project upload` and `cyclecloud project download` CLI commands exited with exit code 0 after failures, which made scripting unreliable. 
- Unrecognized settings added to the `cycle_server.properties` file could cause failures during CycleCloud start-up. 
- CycleCloud UI pages did not always refresh automatically when dialogs were closed with the **Save** button to apply changes. 
- The **Connect** button in the CycleCloud UI gave a misleading error for users without permission to connect to the node. 
- The `ConnectDatasource` plugin incorrectly returned the node password even if node access was disabled. 
- The `userdata` API allowed lower privilege users to query node data. 
- Slurm nodes running SLES 15 continued to reconverge repeatedly even after converging successfully. 
- An authorization issue allowed users to view node operation information from clusters they did not have permission to access. 
- Improved cluster startup reliability at large scale by reducing simultaneous requests to the CycleCloud server. 
- Improved node initialization reliability by retrying downloads of node configuration and user access information after temporary connection or server failures. 
- Improved error messages for failed node initialization to include details returned by the CycleCloud server. 
- Node operation history is now retained for 30 days. Older records, including existing history, are deleted when CycleCloud starts after an upgrade. Status queries for deleted operations return “not found.” 
- CycleCloud nodes requiring legacy Chef support could fail NFS filesystem discovery when multiple nodes were marked as `Discoverable`. 

## Breaking changes 
- The **Return Proxy** option no longer opens a tunnel for the retired AMQP channel to CycleCloud.  If any legacy clusters rely on AMQP and ReturnProxy, they must be upgraded to the latest Jetpack (by terminating the cluster and selecting **Upgrade**).  
- Support for setting initial `Password` for Linux nodes in the cluster template was insecure and has been removed since cluster parameters are stored in plain text.  Prefer [CycleCloud User Management](../concepts/user-management.md?view=cyclecloud-8) or Microsoft Entra for cluster user access.
