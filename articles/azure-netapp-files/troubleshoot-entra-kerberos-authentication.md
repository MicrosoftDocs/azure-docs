# Troubleshoot Microsoft Entra Kerberos authentication for Azure NetApp Files (preview)

Learn about error messages and resolutions you can encounter when configuring and managing [Microsoft Entra Kerberos authentication for hybrid identities](configure-entra-kerberos-authentication-for-hybrid-cloud-identities.md). 

## Errors configuring Microsoft Entra Kerberos authentication

| Error Message | Resolution |
| ----------- | ----------- |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `Active Directory and Entra ID cannot be used together. Account can have either EntraId or Active directory`. | <ul><li>Remove either Active Directory or Entra ID configuration from the account and ensure only one authentication method is configured per account.</li> <li>Delete all dependent volumes before switching between AD and Entra ID.</li></ul> |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `Invalid value received for 'EntraIdconfiguration.dnsDomain' '{domain}', it contains invalid characters or is not in the expected format. Allowed characters are: alphabetical characters (A-Za-z), numeric characters (0-9), minus sign (-), and the period (.). The first character must be alphabetical or numeric, last character must not be a minus sign or a period. Example: domain.com` | <ul><li>Ensure domain follows the format: `domain.com`.</li> <li>Use only allowed characters: A-Z, a-z, 0-9, hyphen (-), and period (.).</li> <li>First character must be alphanumeric.</li> <li>Last character must not be a hyphen or period.</li></ul> |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `The EntraIdConfig's '{propertyName}' property is not allowed to be updated while EntraIdConfig is in use. Please check that '{propertyName}' is not part of the update request or remove all SMB volumes before updating this property.` | <ul><li>Delete all Entra ID enabled SMB volumes before updating these properties.</li> <li>Remove the property from the update request if volumes are using the configuration.</li> <li>Immutable properties when volumes exist: `ApplicationId, Domain, ServerNamePrefix`.</li></ul> |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `Unable to delete Entra Id configuration while Entra Id enabled volume still exists. Please delete Entra Id enabled volumes before deleting the Entra Id configuration`. | Delete all Entra ID enabled volumes first and wait for Entra ID configuration status to change from "InUse" to another state and then proceed with deleting the Entra ID configuration. |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `Unable to create volume as request to create Entra ID server application failed with authorization denied. Please ensure the permissions 'Application.ReadWrite.OwnedBy', 'DelegatedPermissionGrant.ReadWrite.All' and 'User.Read' are assigned to the client application with application id '{EntraIdConfigApplicationId}' provided as part of Entra ID config to create Entra ID server application in the tenant`. | <ul><li>Grant the following permissions to the client application (Application ID from Entra ID config): <ul> <li>Application.ReadWrite.OwnedBy</li> <li> DelegatedPermissionGrant.ReadWrite.All </li> <li> User.Read </li></ul> <li>Ensure admin consent is provided for these permissions.</li> <li>Verify the application ID in the Entra ID configuration is correct.</li></ul> |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `Unable to create volume as the Entra ID certificate '{EntraIdConfigCertifcateName}' present in keyvault '{EntraIdConfigAzureKeyVaultUri}' could not be read due to incorrect formatting. Provide a valid client certificate registered with Azure client application with application id '{EntraIdConfigApplicationId}'`. | <ul><li>Verify the certificate is properly formatted and stored in Azure Key Vault.</li> <li>Ensure the certificate is registered with the Azure client application (Application ID from Entra ID config).</li> <li>Reupload the certificate to Azure Key Vault with correct formatting.</li> <li>Verify the certificate name matches exactly what's specified in the configuration.</li></ul> |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `Unable to create volume as certificate '{EntraIdConfigCertifcateName}' present in keyvault '{EntraIdConfigAzureKeyVaultUri}' is not supported in FIPS mode and requires PKCS12KDF key derivative function. Provide a valid client certificate registered with Azure client application with application id '{EntraIdConfigApplicationId}'`. | <ul><li>Use a FIPS-compliant certificate with PKCS12KDF key derivative function.</li> <li>Ensure the certificate is registered with the Azure client application.</li> <li>Replace the certificate in Azure Key Vault with a compliant one.</li></ul> |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `Failed to retrieve certificate '{certificateName}' from Azure Key Vault '{keyVaultUri}'. Please ensure that the certificate exists and that the access policies grant the necessary 'Get' permissions for the identity from the NetAppAccount {accountName}`. | <ul><li>Verify the certificate exists in the specified Azure Key Vault.</li> <li>Grant 'Get' permission on secrets/certificates to the managed identity (System Assigned or User Assigned) from the NetApp Account.</li> <li>Verify the Key Vault URI and certificate name are correct.</li> <li>Check Key Vault access policies and network restrictions.</li></ul> |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `Failed to retrieve the private key from certificate '{certificateName}' in Azure Key Vault '{keyVaultUri}'. Please ensure that the correct certificate is stored in the Azure Key Vault and try again`. | <ul><li>Upload the certificate with its private key to Azure Key Vault.</li> <li>Ensure the certificate is stored as a certificate (not just a secret) with the private key included.</li> <li>Reupload the complete certificate including the private key.</li></ul> |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `Unsupported private key algorithm used in your certificate '{certificateName}' from Azure Key Vault '{keyVaultUri}'. Please use an RSA or ECDSA signing algorithm for your private key, update your certificate in your Azure Key Vault, and try again`. | <ul><li>Use a certificate with RSA or ECDSA signing algorithm.</li> <li>Update the certificate in Azure Key Vault with a supported algorithm.</li> <li>Ensure the private key uses RSA or ECDSA.</li></ul> |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `Entra ID user assigned identity '{entraIDIdentity}' does not match the user assigned identity on the account. Please make sure that 'identity.userAssignedIdentities' has an identity with the same resource id`. | <ul><li>Ensure the user assigned identity specified in `EntraIdConfig.EntraIdAKVConfig.UserAssignedIdentity` exists in the account's `identity.userAssignedIdentities`.</li> <li>Add the user assigned identity to the NetApp Account.</li> <li>Verify the identity resource ID matches exactly.</li></ul> |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `'{featureName}' cannot be enabled on {resourceType} '{resourceName}' with system assigned identity if resource identity doesn't have system assigned identity. Please make sure that 'identity.type' has a 'SystemAssigned' identity passed in the request or is existing on the NetApp account`. | <ul><li>Set `identity.type` to include 'SystemAssigned' on the NetApp Account or specify a user assigned identity in `EntraIdConfig.EntraIdAKVConfig.UserAssignedIdentity`.</li> <li>Ensure the account has either SystemAssigned or UserAssigned identity configured.</li></ul> |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `NetApp account {accountName}'s identity is not set as SystemAssigned, when entraIdConfig.entraIdAKVConfig.userAssignedIdentity is null or empty. Please set account's identity as SystemAssigned to your NetApp account and try this operation again`. | Enable System Assigned identity on the NetApp Account or provide a user assigned identity in `EntraIdConfig.EntraIdAKVConfig.UserAssignedIdentity`. |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `(Generic message for invalid identity type)` | Configure either System Assigned or User Assigned identity on the NetApp Account and ensure `identity.type` isn't 'None'. |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `An SMB volume can't be set up without a configured Active Directory or EntraId on a NetApp account. Please configure the NetApp Account {accountName} with Active Directory or EntraId settings to use SMB`. | <ul><li>Configure either Active Directory or Entra ID on the NetApp Account and ensure the account has authentication settings before creating SMB volumes.</li></ul> |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `NetApp account {accountName} does not have any user-assigned or system-assigned Managed Identity, however this operation requires a Managed Identity. Please provide a Managed Identity to your NetApp account and try this operation again`. | <ul><li>Configure either System Assigned or User Assigned managed identity on the NetApp Account and ensure that the `identity.type` includes 'SystemAssigned' or 'UserAssigned'.</li> <li>If you are using user-assigned identity, add user assigned identities to `identity.userAssignedIdentities`.</li></ul> |
| The Microsoft Entra Kerberos authentication configuration fails with the following error <br> `The provided identity does not have permission to access the secret '{certificateName}' from Azure Key Vault '{keyVaultUri}' using {identityType} identity. When a certificate with a private key is imported or created in Azure Key Vault, the private key is automatically stored as a secret under the same name as the certificate. Private key secrets are not directly listed in the Azure Portal, but are accessible through Azure CLI, PowerShell, and SDKs. Please ensure that the identity associated with the NetAppAccount '{accountName}' has been granted the 'Get' permission on secrets in the Key Vault`. | Ensure that identity associated with NetApp Account has been granted 'GET' permission on secrets in key vault. |
